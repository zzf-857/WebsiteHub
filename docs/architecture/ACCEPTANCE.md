# 验收规范

总负责人按本文件验收每个条目。执行者在交付前用 §3 自查，交付时按 §5 写报告。

## 1. “做完”的定义（全部满足才算交付）

1. spec 的“功能要求”逐条实现；偏离处在报告里写明原因。
2. spec 的“测试清单”逐条有对应测试，且能在不改测试的情况下证明该行为（删掉实现会失败）。
3. 全量门禁全绿（`CODING_STANDARDS.md` §7.3），测试数只增不减。
4. 不违反 `ARCHITECTURE.md` §6 的任一不变量。
5. 符合 `CODING_STANDARDS.md` 的结构、命名、样式规则。
6. 含界面的条目：执行者自己截图看过（§4），并在报告列出截图路径。
7. 按规范提交到 `qNN-work` 分支并只推送该分支，未改状态文档。

## 2. 总负责人验收流程

| 步骤 | 做什么 | 不通过时 |
| --- | --- | --- |
| A 报告 | 读交付报告，核对 §5 必填项齐全 | 退回补报告 |
| B 差异审查 | `git fetch origin qNN-work` 后 `git diff <基线>..origin/qNN-work` 对照 spec 的“文件清单 / 接口契约 / 测试清单”与 §3 清单 | 列问题退回 |
| C 合并 | 合入主分支；按 `CODING_STANDARDS.md` §6.4 串迁移链；解决冲突 | — |
| D 门禁 | 在合并结果上跑全量门禁 | 由总负责人定位：归属条目退回或小修 |
| E 设计评审 | 含界面的条目：播种数据后截图（浅 / 深 1440、手机 390），逐项对照 §4 清单 | 列问题，派修复轮 |
| F 端到端 | Q57 套件在合并结果上跑通 | 按 Q57 迭代流程修复 |
| G 记录 | 更新 `ITERATION_QUEUE.md` 状态与门禁基线、`PROGRESS.md` 快照，推送 | — |

验收结论三档：**通过** / **有条件通过**（列出跟进项并写入队列）/ **退回**（列出必须修改的问题）。

## 3. 执行者自查清单

后端
- [ ] 所有新查询带 `user_id`；跨账号返回 404 的测试存在。
- [ ] 写接口有 `WriteOriginDependency`（Cookie 路由）或写权限检查（Bearer 路由）。
- [ ] 请求模型 `extra="forbid"`，字段有长度 / 范围约束。
- [ ] 使用信号 / 派生数据不改 `version`、`updated_at`，有测试断言。
- [ ] 外部 HTTP 只走安全出站层；测试无网络访问。
- [ ] 错误信息不含上游原文；日志无密钥 / 令牌 / 完整查询串。
- [ ] 迁移：命名、`server_default`、降级、`DATABASE_SCHEMA_HEADS`、升降级测试。
- [ ] 后台任务有并发上限、退避与持久状态（若用户可感知）。

前端
- [ ] 契约容错旧响应、拒绝格式错误；客户端错误映射有测试。
- [ ] 加载 / 空 / 错误三态都有；错误可重试。
- [ ] 可逆操作乐观更新 + 撤销；破坏性操作二次确认。
- [ ] 只用设计令牌；新令牌三处都定义；圆角 ≤8px；只用允许的 lucide 图标。
- [ ] 图片走 `proxiedImageUrl`；外链 `noopener noreferrer`。
- [ ] 键盘可达、可见焦点、无交互元素嵌套；尊重减少动态效果。
- [ ] 390px 无横向滚动；深色主题对比度正常。
- [ ] 组件 ≤700 行，逻辑在 `lib/` 并有测试。

## 4. 设计评审清单（截图逐项看）

- 层级：每屏只有一个视觉焦点；标题 / 元信息 / 正文字号层次清楚。
- 重复：同一信息不在同一屏出现两次以上。
- 对齐与间距：卡片、列表、按钮落在同一网格；间距一致。
- 状态：加载骨架形状与最终布局一致；空状态有下一步行动；错误态可重试。
- 主题：浅深两套都可读，无“发灰 / 发脏”的底色。
- 窄屏：390px 无横向滚动，无元素互相遮挡，触控目标 ≥40px。
- 一致性：与发现页 / 收藏库的视觉语言一致（封面系统、令牌、按钮层级：主按钮唯一）。

## 5. 交付报告模板（执行者必须按此格式）

```markdown
## Qxx 交付报告

- 分支 / 基线 / 提交：qxx-work · 基于 <hash> · 提交 <hash>[, <hash>]
- 门禁：后端 <N> passed / <M> skipped；Ruff 通过；前端 <T> tests / <P> pass / <S> skip；tsc、eslint、build 通过
- 实现清单：逐条对应 spec「功能要求」编号（R1、R2 …），每条一句话 + 主要文件
- 测试清单：逐条对应 spec「测试清单」编号（T1、T2 …）→ 测试文件::测试名
- 偏差：编号 + 原因（没有写“无”）
- 自查：§3 清单中未勾选的项及原因
- 截图（含界面时）：绝对路径列表
- 未验证 / 风险：真实网络、真实浏览器、性能等无法在环境内验证的点
```
